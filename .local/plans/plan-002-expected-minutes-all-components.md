# Plan 002 — Drive every scoring component from expected minutes (Copilot xMins)

Status: PROPOSED — nothing implemented yet. Awaiting decisions listed at the bottom.
Follows: commit `15ca51d8` (Copilot xMins now drive the 60+ minute chance for clean sheets / goals conceded, Copilot-covered gameweeks only).

## 1. The problem today: three inconsistent ways of treating minutes

| Component | What it does with minutes now | Consequence |
|---|---|---|
| Goals, assists | season share of team goals x team goals x availability ratio | share already embeds past minutes; ratio only rescales availability -> sub with a few hot minutes is inflated (Isidor), a returning starter is under-projected (Konsa-type) |
| Bonus | bonus per appearance x ratio | a 20-minute cameo counts as a full appearance |
| Yellow/red cards, DC, saves | per-90 rate x availability ratio | assumes a full 90 whenever the player is "available" |
| Minutes points | historical minutes points x (adjusted / Copilot base) | needed a cap at 2 after the Benitez bug |
| Clean sheets, goals conceded | (as of 15ca51d8) 60+ chance from Copilot xMins, threshold rule | rotation players averaging 60-89 are treated as certain starters |

The page also promises "Projections assume the player starts the match" — true for cards/DC/saves, only partly true for shares.

## 2. Design principles

1. **One source of expected minutes per gameweek**: `xMinsPerGW` (already includes the player's own availability and teammate reallocation). Use it directly for Copilot-covered gameweeks; never multiply availability in again.
2. **One calibrated minutes distribution, not ad-hoc thresholds.** Copilot gives a *mean*. Every component needs a *distribution* (a 45-minute mean is not a certain 45 minutes). Build `P(minutes bucket | xMins)` once from real data, then every component is an expectation over that distribution:
   - buckets: 0 / 1-29 / 30-59 / 60-74 / 75-90
   - minutes points = 2*P(60+) + 1*P(1-59)
   - clean sheet = P(60+) x team CS chance x 4
   - goals-conceded penalty = sum over buckets of P(bucket) x Poisson penalty(lambda = team GA x minutes/90)
   - DC = sum over buckets P(bucket) x P(DC >= threshold | Poisson(mean = DC per 90 x minutes/90))
   - cards / saves / bonus = rate per 90 x E[minutes]/90 (linear, so E[minutes]=xMins is enough), bonus capped at 3 per fixture
3. **Rates are shrunk by minutes first** (already done: 360-minute shrinkage, capped at teammates' pooled rate) so a small sample can't be multiplied up.
4. **Goals/assists keep team-total consistency**: weight w_i = shrunk goal rate per 90 x xMins_i; goals_i = team projected goals x w_i / sum(w) per team per gameweek. A teammate's absence (xMins 0) automatically redistributes — replaces the ratio hack for covered gameweeks.
5. **Legacy path stays for uncovered gameweeks** (Copilot's export only forecasts ~6 gameweeks; beyond that xMins is a flat per-appearance history average, too thin — e.g. a keeper with one 90-minute game would look like a certain starter). Known cost: a visible step at the window boundary (already exists today).
6. **Product semantics change**: headline numbers become "expected points including minutes risk". Page note and Mins column must say so.

## 3. Calibration of P(minutes | xMins)

- Data in DB: `gameweek_player_data` has 2025/26 (38 GWs, ~29k rows) + 2026/27 so far.
- Historical xMins forecasts don't exist, so use a proxy: trailing mean of the player's last 5 team-games' minutes (zeros included) as `x`, bin x, tabulate realised minutes next gameweek. Ship as a static table in `shared/minutes-distribution.ts`, generated by `scripts/calibrate-minutes-distribution.ts`.
- Tests: E[minutes | x] ~ x within tolerance; P(60+ | x) monotone increasing; rows sum to 1.
- Limitation: Copilot's x also bakes in injuries/news, the proxy doesn't. Mitigation: validate against realised results (section 6) and re-calibrate from real Copilot snapshots once enough accumulate (see Phase 5, snapshot history).

## 4. Phases (each: tests first, local commit, deploy only on request)

- **P0 — Calibration**: script + table + tests above. No behaviour change.
- **P1 — Minutes points, clean sheets, goals conceded** use the calibrated distribution (supersedes the "60+ = full credit" rule from 15ca51d8 where they differ, e.g. a 65-minute rotation player).
- **P2 — Cards, saves, DC**: rate x minutes (DC and goals-conceded via bucket mixture).
- **P3 — Goals, assists, bonus**: weights x xMins with per-team normalisation; bonus per 90 x minutes.
- **P4 — UI**: Player Points "Mins" column shows Copilot xMins per gameweek; replace `projection-disclaimer.tsx` wording; optional "assume starts" toggle.
- **P5 — Validation and history**: (a) read-only comparison of our totals vs Copilot's own per-gameweek xPts (already stored in `copilot_xmins_projections.x_pts`) — flag large disagreements, don't treat Copilot as truth; (b) keep a snapshot history of Copilot uploads so forecasts can be back-tested against realised minutes/points; (c) feed old-vs-new into the existing projection-accuracy tracking so the arbiter is realised points.

Rollout safety: behind an admin setting (like goal `calculationMode`) with shadow comparison before it becomes default, so old numbers remain reproducible.

## 5. Risks

- Calibration proxy mismatch (above) -> mitigated by validation + re-calibration.
- Normalised goal weights depend on the whole squad's xMins; one bad Copilot row moves teammates. Mitigate: validator already rejects malformed exports; add a sanity check (sum of squad xMins per team per GW within plausible range).
- Rotation players drop noticeably in headline totals (intended, but visible).
- Existing consistency tests assume the current formulas (cached vs live, team sums); each phase updates them test-first.
- GW39 (TBC) has no per-gameweek xMins -> stays on the legacy formula.

## 6. Decisions needed from the user

1. One mode ("expected points incl. minutes risk") or keep a toggle for "assumes starts"?
2. OK to supersede the "60+ expected minutes = full clean-sheet credit" rule with the calibrated curve (more accurate for rotation players, different from the rule agreed on 2026-10-15)?
3. Beyond Copilot's ~6-gameweek window: keep the legacy path (recommended for now), or extend Copilot's last-known role forward with decay?
4. Store Copilot upload history (small table) to enable real back-testing?
5. Start with P0 + P5(a) (calibration + Copilot xPts comparison) since they change no numbers and sharpen every later decision?
